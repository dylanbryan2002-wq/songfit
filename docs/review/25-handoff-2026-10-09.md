## 2. The product and the engine, as they stand

Songfit (thissongfits.com, branch `mvp`, Next.js + Supabase + Anthropic SDK + Deezer): creator uploads a
Reel, engine returns 3 songs with start/end and a reason. Engine stages (`src/engine/`):

analysis (Fable 5.1, 1 fps frames + Whisper) → candidates (Sonnet 5.5, three directions safe / current /
unexpected, 25 each, effort medium, 12k token cap, low-effort retry on truncation) → Deezer
verification (samples-only rule: no 30 s preview, no recommendation) → scoring (6 model dims in one
batched call + rule dims `dialogue.ts`, `overuse.ts`; weights in `weights.ts`; all stored as
`component_scores` jsonb on the candidate row) → diversify (15 picks, rank 1 best fit, rotates
directions, artist tolerance 0.1) → sections → explain (creator copy, reads top-2 component reasons).

Current prompt versions on `mvp`: `candidates-v6`, `scoring-v4`, `judge-v1`, `gemini-paste-v1`.
Engine fixes merged this week (all tests pass, 630 at last count):

  that fits beats a tasteful obscure one; dialogue → quiet bed examples (klsr, American Dawn, Grant

- scoring-v4: `SONG_CARRIES_EDIT_RULE` when no dialogue; `STOCK_CHOICE_RULE` only with dialogue;

Scripts (`scripts/groundtruth/`, run with `pnpm local scripts/groundtruth/<file> ...`):
- `run.ts --root <batch> --tag <tag> [--only <id>] [--force] [--skip-gemini] [--skip-ours] [--dry-run]`:
  runs our engine on each clip (cached at `work/<id>/ours.<tag>.json`; retries cached runs that have
  `recommend_error`; counts them as errors), compares with truth, writes `reports/<date>-<tag>.md/json`
  (summary, headline test table, All / Test / Tune / Song-carries / Quiet-bed columns, judge and
  rating lines).
- `judge.ts --root <batch> --tag <tag>`: head-to-head, real song vs our rank 1, shuffled, `judge-v1`,
  `MODELS.analysis`. Writes `work/<id>/judge.<tag>.json`.
- `fingerprint.ts`: ACRCloud identify (keys in env, entered by Dylan; signature v1 HMAC-SHA1 over
  `POST\n/v1/identify\n<key>\naudio\n1\n<ts>`; `play_offset_ms` is the song position at the END of the
  sample, so start = offset/1000 − sample_end). Prefers `work/<id>/no_vocals.wav`. `applyToCsv` fills
  empty rows and cross-checks known ones.
- `separate.sh`: demucs (htdemucs, two stems) on clips with no match or score < 90; `--all`.
- `catalog.ts` (sounds.csv), `split.ts`, `rating-sheet.ts` / `rating-apply.ts`, `intake.ts`,
  `ours.ts`, `gemini.ts` (+ `GEMINI_PROMPT.md`, the exact prompt Dylan has), `compare.ts`, `report.ts`.
- Running the eval: one worker per batch in a background shell, loop over clip ids with `--only`.
  Four workers overloaded the Mac (load 28, ffmpeg 90 s timeouts); two is the max.
  Deezer ~10 req/s tolerated with retry. One clip ≈ 100–200 s; 33 clips ≈ 1 h per worker; ≈ $20 per batch.
